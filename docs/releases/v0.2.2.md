A reliability release: seven bug fixes, no new features, and nothing to migrate. Your vault, notes and project identities work as before.

## 🪨 What's fixed

**Your memory stays in the right project** (#1)
Two repos with the same folder name (`api`, `backend`, `infra`…) but different remotes no longer share memory. Before, a checkout of `gitlab.com/someone-else/api` loaded your `api` project's notes and saved new facts into it. Now a repo with a remote only matches a project with that remote, and a new repo whose folder name is taken gets a project named after its remote (`someone-else-api`).

**Several agents at once, nothing lost** (#3)
Claude Code and Copilot (or two sessions) saving at the same moment could collide on git: one save came back with `not committed`, and read counts could be lost. Every agent's server now takes a shared lock on the vault while it writes.

**Updates keep your tags** (#4)
Updating a note no longer drops the tags it already had, including the ones you added in Obsidian. Repairing a note with broken frontmatter is now recorded as an update, not a creation.

**Search finds CI, DB, Go** (#6)
Two-letter terms are now searchable, as whole words (`db` no longer matches `feedback`). Filler words like `to` or `is` are ignored.

**No more invisible notes** (#2)
A title with no letter or digit (`???`) is refused instead of being saved as a hidden `.md` file that never showed up in the Index.

**Save reminders count per session** (#5)
The stop hook's counters keep only safe characters of the session id, clients that send no session id no longer share one counter, and counters from finished sessions are cleaned up.

**Copilot runs the plugin you installed last** (#8)
With several copies of the plugin installed, Copilot's hooks and MCP server use the newest one instead of the first by name.

## ⬆️ Upgrading

Update the plugin from its marketplace as usual, in Claude Code and in Copilot; the launcher downloads and verifies the 0.2.2 binary on first use.

One behaviour to know: a project now matches a checkout by remote when it has one. If a repo was renamed or moved and its local remote URL changed, add the new remote to `Projects/<project>/_project.md`, or its notes won't load there.
