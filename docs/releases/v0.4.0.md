Memory that stays good. 0.4 is about quality: code now finds what goes wrong in a memory (duplicates, stale paths, unused notes, summaries too long), the cleanup reviews every note of a vault up to 300 notes in pages every agent reads whole, and session start reminds you when a cleanup is due.

## 🪨 What's new

**A cleanup review sized for every agent** (#77, #89)
`tidy-memory` hands its review to the `memory-cleanup` subagent in pages of 3 KiB, small enough for every agent to read inline, Antigravity CLI included. Up to 300 notes, every cleanup reviews every note. Above that, your preferences, the folders that changed since the last cleanup and the folders you use come first, up to 10 pages. "Review my whole memory" reviews everything, whatever the size. The last cleanup is recorded in `.last-cleanup` in the vault, committed with the notes.

**Problems found by code, across the whole vault**
`petit-poucet check`, and every cleanup review, now report:
- near-duplicate notes, one short line per note (#36);
- notes naming a file or folder gone from their project's checkout (#23);
- notes nobody read, wrote or updated for 90 days, once usage has counted that long; `feedback` notes are never listed (#25);
- summaries over 200 characters, and sessions that load more than 100 notes (#14).

**Reminders, not surprises** (#84)
Session start tells you when a cleanup is due: more than 30 notes changed, 30 days since the last one, or a vault of more than 30 notes never cleaned. The rules your agent receives now ask it to fix a note it finds wrong or outdated on the spot, and to say so.

**Usage that travels with the vault** (#88)
Read counts and the projects your sessions load live in the vault, one file per machine in `.usage/`, so they add up across machines and never conflict. They ride along with commits that happen anyway: reading a note never makes a commit of its own.

**Migration from every agent** (#22)
The `migrate-memory` skill looks for the instruction files and own memories of every supported agent: Claude Code, GitHub Copilot (VS Code's memory tool included), Codex memories, Cursor rules and Antigravity CLI rules and knowledge.

**Settings in one place** (#89, #96)
`~/.config/petit-poucet/config.toml` holds every limit above with its value. A setting added by a newer version is written in the first time the file is read, keeping your own lines and comments.

## 🔧 What's fixed

- On Windows, a file another process was reading could not be replaced: a note save failed with "Access is denied", and the background update check could lose its result (#101).

## ⬆️ Upgrading from 0.3

Run the install script again:

```sh
curl -fsSL https://raw.githubusercontent.com/areguig/petit-poucet/main/install.sh | sh   # macOS, Linux
irm https://raw.githubusercontent.com/areguig/petit-poucet/main/install.ps1 | iex       # Windows, PowerShell
petit-poucet setup
```

Your vault and notes don't change. The first session moves your read counts from `.petit-poucet/usage.json` into the vault, and the config file gets the new settings. Run `setup` once so every agent gets the updated skills and `memory-cleanup` subagent. Your first cleanup reviews every note.
