A session start that always fits: your agents now load your memory within a byte budget every harness accepts, and say what they left out. Preferences become a curated list, each one saying when it applies, and `petit-poucet doctor` checks your installation in one read-only report.

## 🪨 What's new

**A session start that always fits** (#212)
Some agents cut the text a hook gives them (Claude Code at about 10,000 characters), so part of your memory never reached the model. The session start is now budgeted in bytes, `session_start_max_bytes` (8,000 by default): preferences first, then the project's notes, topic names and sync conflicts, each line whole or not at all. When something doesn't fit, a "Not loaded" line names it and `memory_index` pages through the rest. `memory_save`, `check` and the session start warn when your memory grows past the budget. `session_start_max_bytes` replaces `index_max_notes`.

**Short note names** (#214)
The session view names notes by the first words of their file name, as few as no other note shares, such as `[[commit-rules]]`, so more of your memory fits. Every tool accepts that name, and `memory_save` stores a link written with it by the note's full path, so `check`, Obsidian and moves keep following it (#246).

**Preferences that say when they apply** (#215, #216)
A preference can carry `applies_when`, such as "editing Rust code". It stays cross-project but out of the session start, and `memory_search` finds it when the situation comes up. Saving a new preference reminds your agent to check that it really is cross-project and when it applies. `tidy-memory` proposes which of your preferences are situational, in batches you review; nothing moves without you.

**What memory is for** (#213)
The session rules and the save reminder now say what memory is for: what a later session can't find again, such as your decisions, rules and corrections, and facts your agent verified that the code, git history or docs don't already record.

**`petit-poucet doctor`** (#95)
One read-only report on your installation: the binary and your PATH, your config, the vault and git identity, each agent's wiring and the session start it would get here, sync conflicts and the machines you sync with. Each problem names the command that fixes it. It exits 0 when healthy, 1 for errors and 2 for warnings only.

## 🔧 What's fixed

- An update or a move keeps the frontmatter keys you added, such as Obsidian's `aliases` and `cssclasses` (#232).
- `memory_move` refuses a new name that isn't a file name like the ones `memory_save` makes, so no line break or `]]` reaches the Index, and on Windows no `\` leads outside the vault (#230).
- A cleanup review keeps the same pages and page count from page 1 to the last, instead of moving as the cleanup changes notes (#199).
- `check` no longer calls a path missing when it is deeper in the project's checkout or in another project's checkout on this machine (#200).
- `check` names the full path a broken link most likely means (#246).
- A short name written with its folder in front, such as `Topics/lab/short-name`, finds the note like the short name alone (#253).

## ⬆️ Upgrading from 0.7

```sh
petit-poucet update
```

Your notes don't change. If your config sets `index_max_notes`, it is dropped: set `session_start_max_bytes` instead if you need another budget. Restart your agents, then run `petit-poucet doctor`. To make some preferences situational, ask your agent to tidy your memory.
