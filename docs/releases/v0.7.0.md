One memory on several machines: petit-poucet now shares the vault between your laptop, your desktop and a home server through Syncthing, peer to peer and without a cloud, and works with Hermes Agent. Agents can install and update it for you.

## 🪨 What's new

**Several machines, through Syncthing** (#81)
The vault now works under Syncthing. Each machine keeps its own git history, Index and state; notes, usage counts and the last cleanup time sync. At session start, petit-poucet indexes and commits the notes that arrived from another machine. A note changed on two machines at once leaves a conflict copy: your agent is told, merges it with you, and `check` lists it. A project is matched on each machine by its git remote, wherever it's checked out.

**`petit-poucet sync`** (#134)
Pairs two machines in one command on each side: run `petit-poucet sync`, then the command it prints on the other machine. It shares the vault in the Syncthing you installed, lists the machines it syncs with, and says how to install and start Syncthing when it's missing. petit-poucet never ships or runs Syncthing. Step by step: [several machines](https://github.com/areguig/petit-poucet/blob/main/docs/syncthing.md).

**Keep some notes on one machine** (#146)
Syncthing never syncs `.stignore`, so each machine can leave out more: a line such as `/Projects/acme-billing` keeps a work project off a home server. `sync` lists the machine's own lines.

**Hermes Agent** (#133)
`petit-poucet setup` now wires Hermes Agent: the MCP server and a `pre_llm_call` hook in `~/.hermes/config.yaml`, written through `hermes config set` so your comments stay, and the `memory` and `migrate-memory` skills. Your memory joins the first message of each session. Open `hermes` once and approve petit-poucet's hook when it asks. Hermes has no hook after an answer, so it gets no save reminder, and its subagents come from no file, so tidy your memory from another agent. `migrate-memory` now reads Hermes's `MEMORY.md` and `USER.md`.

**Install and update through your agent** (#149)
Ask any agent with a shell: "Install petit-poucet for me: follow https://areguig.github.io/petit-poucet/install.md". The guide tells it what to run, how to check, and what to tell you. The install scripts print the full path when their folder isn't on your PATH yet, and the release notice says your agent can run `petit-poucet update` for you.

**A new site** (#150)
The tale, how it works, several machines, and install through your agent, with self-hosted fonts: the site makes no third-party requests.

## 🔧 What's fixed

- Vault commits name Claude Code again, instead of "unknown agent" (#106).
- Agents resolve sync conflicts with their memory tools (#137).
- `setup` works on an existing vault when git has no identity yet, and says so (#140).
- `setup` says "found" for a vault already in place, instead of "created" (#144).
- petit-poucet's own `.stignore` lines come first, since Syncthing applies the first line that matches: a line of yours can't sync git history or machine state (#154).
- A sync conflict on a project's `_project.md` is merged at session start, keeping the remotes and folders of both versions (#155).

## ⬆️ Upgrading from 0.6

```sh
petit-poucet update
```

It installs 0.7.0 and runs `setup`, which adds the new ignore lines to your vault (`.gitignore`, `.stignore`) and commits them; your notes don't change. Restart your agents. For several machines, install Syncthing and run `petit-poucet sync`: [several machines](https://github.com/areguig/petit-poucet/blob/main/docs/syncthing.md).

## 🧪 Under the hood

- A real two-instance Syncthing test runs on Linux, macOS and Windows, and a four-machine trial with real Claude Code checks the whole flow before a release (#145).
- A CI job installs petit-poucet into the real Hermes Agent on Linux, macOS and Windows and runs a session against a mock model, with more memory than Hermes passes on by default.
- Tests resolve every agent's folder inside their throwaway home, whatever `CODEX_HOME`, `COPILOT_HOME` or `HERMES_HOME` say (#158), and each agent's CI job checks that profiles outside it are left untouched.
- The Hermes job retries its installer download when GitHub rate-limits it (#160).
